# Hundred Years' War: link-based similarity

Portfolio and learning project for Amos (data science internship search). Explain each step; plan (plan mode) before each new roadmap step. Analysis goes in Jupyter notebooks, run in VS Code with the `.venv` kernel. Keep the narrative lean: make decisions and justify them in a sentence, rather than testing every option.

This is a simplified rebuild of `~/Documents/GitHub/hundred-years-war-network` (the exploratory version, kept as an archive). Lessons from it appear here as one-line justifications.

## Roadmap
1. **Collect and explore** (`notebooks/01_collect_and_explore.ipynb`).
2. **Milne–Witten similarity** (`notebooks/02_milne_witten.ipynb`).
3. **Article types** (`notebooks/03_article_types.ipynb`): Amos's hand labels on a random sample of 200 (`data/labels/labels.csv`, codebook `data/labels/codebook.md`, first version `labels_original.csv`), a text-only classifier (TF-IDF + logistic regression on title, short description and first paragraph; never links, so comparing types with link-based themes isn't circular) for the rest, evaluated by repeated stratified 5-fold CV. Agreement with themes (crosstab, ARI, NMI) uses hand labels only; predicted types feed the page filter, marked as predicted.
4. **Clustering** (`notebooks/04_clustering.ipynb`): unsupervised, on Milne–Witten similarity; metadata only describes the clusters. Evaluated by silhouette, stability and inspection. No labels of *relatedness to the seed* (they'd make a classifier seed-specific, and every article was selected by the seed's links); article *types* are a separate variable (Step 3).
5. **Graph and UI** (`notebooks/05_graph.ipynb` → `docs/index.html`): static page, radial view (angle = theme, radius = closeness) and network view, with an animated toggle.
6. **Search** (`notebooks/06_search.ipynb`): BM25 from Info 202 HW4 over title + first paragraph, exported to `docs/search.js`.

## Decisions
- **Nodes:** the seed (*Hundred Years' War*) plus every article it links to, excluding disambiguation pages: 789 articles.
- **All links, via the API** (`generator=links`, redirects resolved). Dropped: red links, self-links, citation identifiers (redirects named "… (identifier)"), the *Wayback Machine*.
- **`from_template`** in the links table: True when a link isn't in the article's own source text (wikitext), i.e. a navbox, sidebar or other template added it. This includes links that a citation template builds from a parameter (e.g. `author-link=John Le Patourel`); only `[[...]]` links count as written. Kept as a signal for clustering, not analyzed further. (In the exploratory version, navbox links made up 65% of network links and inflated every link measure.)
- **Milne & Witten (2008):** out-link measure (cosine of link vectors weighted log(N / df), with df counted over our 789 articles instead of all of Wikipedia) and in-link measure (1 − Normalized Google Distance on in-links from all of Wikipedia; with only the network's in-links the formula breaks). Combined as the **average of percentile ranks**, because in-link values (median ~0.49) are ~100× larger than out-link values.
- **Clustering (Step 4):** Louvain communities (networkx) on a kNN graph (K = 10, edges weighted by Milne–Witten), seed excluded (788 articles). Metadata and `from_template` only *profile* clusters: size would group by length, and templates would rebuild navboxes. Not hierarchical: average linkage gives one cluster of 765 yet a higher silhouette. Cluster names are keyed by a member article (`NAMES` in the notebook), because Louvain's numbering can shift. Names are chosen from five pieces of evidence per cluster (10 most central, type make-up, short-description words, least central members, navbox overlap via `wiki.get_template_links`), with two worked examples in notebook 04 (Lancastrian: clean, its top 10 share 42 links, 92% template-added; Edwardian: core vs scholarship edge). Renamed 27 Nov 2026 after looking beyond the core: Edwardian phase → *Edwardian phase and cited scholarship*, Joan of Arc → *Joan of Arc and her legacy*, Other Anglo-French wars → *Anglo-French conflicts beyond the war*.
- **Graph page (Step 5):** positions computed in Python (`src/layout.py`), the browser only animates between them. Network view: the force layout with each theme then moved as a block away from the center (`spread_clusters`, factor 1.0), because the raw layout overlaps heavily; this exaggerates separation (2-D silhouette 0.17 → 0.47, vs 0.21 on the similarities), so the page notes it in that view. Radial: wedges sized by cluster and ordered by between-cluster similarity (optimal leaf ordering); radius = 0.08 + 0.92·√(rank / 788), so equal-area rings hold equal numbers of articles. Look: Wikipedia's default theme (white page, serif headings in Linux Libertine/Georgia, link blue #3366cc, grey hairlines #a2a9b1, flat grey buttons, Read/Edit-style tabs, a hatnote, [1] footnote with a References section, the details card as an infobox with the article's lead image fetched live from Wikipedia's page-summary API, the related table as a wikitable, the filter pane as a Contents-style sidebar with [hide]); light by default, Wikipedia night colors only under data-theme="dark"; footer credits Wikipedia text under CC BY-SA 4.0 and says the project isn't affiliated with Wikimedia. Color = closeness (one blue ramp), not cluster: 12 clusters exceed the 8 distinguishable hues, so themes are shown by position, labels and legend highlighting. Data in `docs/data.js` (`window.GRAPH`), not JSON, so the page works from `file://`. d3 7.9.0 from cdnjs. `docs/` is ready for GitHub Pages. Page layout: a top bar with the title and **tabs**; below it a one-line intro, then the controls row (view toggle, search, Reset view and a **Filters** button that shows or hides the filter pane, remembered per browser in localStorage, hidden by default on narrow screens, showing the number of ticked options). Tabs: Summary (`docs/summary.html`, a one-page visual summary with its charts in `docs/summary/`; a static copy of a claude.ai artifact, so edit the repo copy) and notebooks 01–06 on GitHub, opening in a new tab. Page features: checkbox filters in a pane on the left, Theme and Article type as dropdowns (theme, sorted closest first; article type from Step 3, sorted closest first, with a note that most are predicted and "(predicted)" on the type tag; closeness; links back; "% of outlinks in network" = `pct_out_degree`, the share of the article's own links that go to the set, in bins under 5% / 5–10 / 10–20 / 20–40 / over 40% (exported to 6 decimals so bins match notebook figures); length; bridge; OR within a filter, AND across), each option showing how many articles ticking it would give. A stats bar on top describes the filtered articles vs the war, each with the all-articles value: count, median rank, mean Milne–Witten, mean in-link, mean out-link, % linking back, median words, themes covered (flagged below 5 articles); the selected article's own values are only in the infobox. Filter options are in link blue, with no explanatory notes under them. The details card shows to the left of the graph only while an article is selected (300px, scrolls inside, no stats, which are in the bar). The graph's height fits the window below the header (`fitChart`: never cut off at the bottom, min 320px). On the graph: a minimizable "How to read it" note (bottom-left, text follows the view) and the closeness color legend (bottom-right, with the network-view note above it). The section filter (where the war's article links to an article) was removed on 27 Nov 2026, and with it the `sections`, `channel`, `from_template` and `centrality` fields in `data.js` and `wiki.get_prose_links`. The table of the 10 most related articles (to the selection, or to the seed) follows the filters, using every pair's scores (`pairs` in `data.js`: upper triangle, 2-byte integers in base64, ~2.5 MB). Search bar: BM25 (k1 = 1.2, b = 0.75) over title + first paragraph (HW4 used paragraphs only; titles added because 70 titles have words missing from their paragraph), the Info 202 HW4 code in `notebooks/06_search.ipynb`, which exports the index to `docs/search.js`; the page ports the scoring to JavaScript (scores match the notebook), puts an exact title match first, and shows the top 8 with snippets. Seed searchable as "Hundred Years' War (Seed)"; Reset clears zoom, filters, selection and search. Filtering on closeness and then reading median rank is circular; the interesting combinations filter on other variables.

## Code and data
- `src/wiki.py`: API calls, cached as JSON in `data/raw/` (gitignored). `get_link_channels` (where on the seed's page each article is linked: body text, infobox, template...; used in notebook 01) parses the seed's wikitext with mwparserfromhell; `get_template_links` lists a navbox's articles (notebook 04). `src/similarity.py`: the measures (`to_pairs` / `from_pairs`). `src/clustering.py`: `neighbors`, `knn_graph`, `louvain`, `stability`, `outside_share`. `src/layout.py`: `network_layout`, `spread_clusters`, `cluster_order`, `radial_layout`.
- `docs/`: `index.html` (the page, d3), `summary.html` + `summary/` (the one-page summary), `search.js` (BM25 index, written by notebook 06) and `data.js` (written by notebook 05, including every pair's scores; regenerate after changing clusters).
- `data/processed/`: Parquet tables (committed) and CSV copies without the text column (gitignored, written by the notebooks):
  - `articles` (one row per article: title, pageid, is_seed, shortdesc, first_paragraph, word_count, n_links_out, out_degree, pct_out_degree, in_degree, links_to_seed, from_template = whether the seed's link to the article came from a template, empty for the seed; text)
  - `links` (source, target, target_in_network, from_template = whether the source's link to the target came from a template)
  - `pairs` (a, b, outlink, inlink, milne_witten; 310,866 rows) and `seed_similarity` (each article's three scores and ranks vs the seed)
  - `article_types` (title, type, type_source = hand / predicted; 788 rows, Step 3)
  - `clusters` (title, cluster, cluster_name, centrality = mean similarity within the cluster, outside_share = share of the 10 nearest articles in other clusters; 788 rows)
- `data/raw/`: `templates/` (navbox link lists, fetched 27 Nov 2026), `links/`, `articles/`, `backlinks/` (copied from the archive repo; collected 29 Sep – 6 Oct 2026), `written_links/` (8 Oct 2026), `_article_count.json` (W = 7,248,637).

## Findings so far
- **Step 1:** 789 nodes, 48,006 network links; the seed links to 452 articles only through templates, 275 in its body text (`get_link_channels`); 66% of 1-hop articles link back to the seed. Templates add 58% of all links and 69% of network links (57% of the seed's).
- **Step 2:** in-link top 10 for the seed = the war's core (Edward III, Charles VII, Henry V, Poitiers, Crécy, Agincourt, Black Death); out-link top 10 = navbox groups (war phases, 1429 Loire campaign). Out-link vs in-link Spearman 0.42; the rank average correlates 0.83 / 0.84 with each. Crécy–seed: in-link 0.755 (|A| = 518, |B| = 2,752, shared 266). Kingdom of England ranks 133rd, Norfolk Record Office 755th. Template-linked articles score higher on all three measures (Milne–Witten 0.84 vs 0.75).
- **Step 4:** 12 Louvain clusters. Stability: ARI 0.89 across seeds (11–13 clusters), 0.79 on 80% subsets, 0.77 for K = 15 (K = 5 gives 16 clusters). Silhouette 0.21 (average linkage, 5 clusters: 0.28 with 765 articles in one). Closest themes to the seed (median rank ~230–260): Lancastrian phase, medieval society, Joan of Arc; farthest: Edwardian phase (56 of 120 are scholarship and media at its edge, nearest to each other: 61% of their 10 nearest are scholarship too), towns, war in general. Three clusters largely rebuild a navbox: Medieval society 75/78 in *Middle Ages*, Middle Ages in Europe 93/119 in *History of Europe*, Joan of Arc 63/67 in *Joan of Arc*. Template share ranges 0–94% (medieval society 94% = navbox echo; monarchies and towns 0–22%). Bridges: Battle of Jargeau (Lancastrian ↔ Joan of Arc), Feudalism, Kingdom of France.

- **Topic focus:** `pct_out_degree` vs seed rank, Spearman −0.75; median rank 698 (under 5% of links into the set, 140 articles) → 174 (over 40%, 222). Partly built in: the out-link half of Milne–Witten counts these same links.
- **Step 3:** 11 types (codebook in `data/labels/codebook.md`). 249 hand labels: 199 by Amos (random sample, the only ones used for evaluation and for comparing with themes) + 50 by Claude in active-learning round 1 (least-certain articles, approved by Amos; `source` column in `labels.csv`). CV on the random sample: macro-F1 0.67 ± 0.02, accuracy 0.77 (baseline 0.18); "other" is never predicted (hand only). Merging confused pairs gains ≤ 0.03, so categories stay. Predicted shares drift as the confusions predict (battles 20% vs 15%, periods 17% vs 10%; events, institutions, military concepts under-predicted). Types vs themes (random sample): ARI 0.25, NMI 0.48. Median seed rank by type: battles 223, periods and culture 278, polities 369, people 398, wars 424, events 480, scholarship 586, places 649, military concepts 671. Output: `data/processed/article_types.parquet` (title, type, type_source = hand / predicted).

## Ideas not yet built
- **Mentions of an article in the seed's text** (not just links: Wikipedia links a term only once, so 214 of 275 prose articles are linked once). Counting names is noisy: aliases are ambiguous ("French" → French nationalism, "Henry"). Articles mentioned 4+ times have median rank 168 vs 498 for 0–1 mentions with a strict alias rule.
- **Time period** (before / during / after 1337–1453, from years in the short description) and **popularity** (all-Wikipedia in-link count, to show NGD's penalty on big general articles).

## Gotchas
- **Data collected on different days:** link lists (29 Sep) and written links (8 Oct) can disagree when a page changed in between; get_written_links matches against the cached link titles first, which absorbs page renames.
- **Pagination:** 500 results per response plus a `continue` token; a page can appear in two batches, so `_query_all` merges by title.
- **Rate limits:** HTTP 429 → `_api_get` waits and retries, as for `maxlag`.
- **Citation identifiers** arrive already resolved (e.g. *Digital object identifier*), so they're recognized by the redirect's original name.
- **The API User-Agent** carries the GitHub URL. Never an email address: the repo will be public.
